# CHG-0002 — Development Branch Governance and Protection Waiver

**Status:** APPROVED / APPLIED  
**Date:** 2026-09-21  
**Affected baseline:** BL-ARCH-001  
**Resulting baseline:** BL-ARCH-002

## Reason

GATE 2G introduced the first real GitHub Actions CI workflow. During repository-governance setup,
GitHub returned HTTP 403 for branch-protection administration on the current private repository:

```text
Upgrade to GitHub Pro or make this repository public to enable this feature.
```

The repository will remain private and no plan upgrade is required for this project.

The project owner also approved moving normal ongoing development to a dedicated long-lived
`dev` integration branch after GATE 2G.

## Approved changes

1. `main` remains the stable milestone/release/baseline branch.
2. `dev` becomes the long-lived integration branch for normal development.
3. Short-lived Issue-linked feature/chore/fix branches are created from `dev`.
4. Normal feature Pull Requests target `dev`.
5. `dev → main` occurs through an explicit Pull Request at approved milestone/release points.
6. Direct development on `main` and `dev` is prohibited by project policy.
7. GitHub Actions CI runs for Pull Requests and pushes on both `dev` and `main`.
8. Required CI check names remain `lint`, `test`, and `migration-check`.
9. Native GitHub branch protection is not a GATE 2 exit requirement under the current private-repository plan.
10. The absence of native protection does not waive the documented PR/review/CI workflow.

## Impact

This changes the frozen engineering workflow in BL-ARCH-001 and therefore requires a superseding
architecture baseline.

No application/domain/data architecture is changed.

## Decision

Approved and applied.

BL-ARCH-002 supersedes BL-ARCH-001.
