# CHG-0007 — Gate 4 Team Lead Verification Governance

**Status:** PROPOSED / PENDING TRANSITION MERGE  
**Issue:** #92  
**Gate:** GATE 4 — Production Readiness, Release Hardening & Bonus Enhancements  
**Classification:** Repository governance / control-plane change  

## Trigger

Gate 3 CHG-0005 replaced mandatory independent peer approval with Team Lead Verification, but it was explicitly scoped to Gate 3 only.

Gate 4 initially reopened the normal independent peer-review requirement. The repository owner / Team Lead has since explicitly directed that reviewer requests must not be mandatory and that PRs should remain open for the Team Lead's own review and manual merge decision.

Gate 4 therefore needs its own explicit governance record rather than silently extending CHG-0005.

## Decision

After CHG-0007 becomes effective, Gate 4 PRs use **Team Lead Verification** as the mandatory human merge gate.

A Gate 4 PR may be merged only after the Team Lead verifies, as applicable:

- Issue-linked scope and correct target branch;
- branch synchronization with current integration state;
- required CI green;
- architecture and frozen-baseline compatibility;
- model/migration intent;
- production/runtime/security/privacy implications;
- documentation synchronization;
- material automated/manual findings resolved or explicitly accepted with evidence;
- explicit Team Lead merge authorization.

Independent peer review remains welcome and optional. It is not a Definition-of-Done, Issue-closure, Gate-closure or milestone prerequisite by itself.

No reviewer is automatically requested merely to satisfy process.

## Standard Gate 4 flow

```text
Issue
→ short-lived branch from current dev
→ implementation/tests
→ Pull Request to dev
→ required CI green
→ material findings resolved/accepted with evidence
→ Team Lead Verification
→ explicit Team Lead merge decision
```

The final Gate 4 milestone uses the same rule with `dev → main` as the PR direction.

## Assistant / automation merge boundary

Automation or assistant work may:

- create/update branches and PRs;
- implement scoped changes;
- run/inspect CI;
- fix material review findings;
- prepare verification evidence and documentation.

It must **not** merge a Gate 4 PR unless the repository owner gives an explicit per-merge instruction that overrides the standing no-assistant-merge rule.

## Technical controls preserved

CHG-0007 removes only mandatory independent peer approval as a process gate. It does **not** relax:

- CI requirements;
- change-control requirements;
- frozen architecture/data/application baseline compatibility;
- security/privacy review;
- migration/schema review;
- production verification requirements;
- material finding resolution;
- explicit Team Lead accountability.
