# CHG-0005 — Gate 3 Team-Lead Verification Merge Workflow

**Status:** APPROVED BY TEAM LEAD / EFFECTIVE ON MERGE  
**Date:** 2026-09-30  
**Issue:** #66  
**Affected governance:** Gate 3 execution workflow, Definition of Done, Gate 3 milestone promotion  
**Affected baselines:** no architecture, data, or runtime baseline change

## Purpose

Replace the mandatory independent peer `APPROVED` requirement for Gate 3 Pull Requests with a documented Team Lead Verification gate.

This change is governance-only. It does not alter application behavior, architecture, data models, migrations, settings, runtime topology, security invariants, or the frozen Gate 0–2 baselines.

## Context

Gate 3 originally required:

```text
Issue → branch → implementation/tests → PR → CI → independent peer review → merge
```

In practice, the active team is small and several otherwise verified Gate 3 PRs have been merged under explicit team-lead authorization without an independent `APPROVED` review. Treating every such merge as a new Governance Exception adds audit churn without improving the technical verification path.

The project owner/team lead has explicitly decided that independent peer approval must no longer be a mandatory merge gate for the remainder of Gate 3.

Historical PRs merged before CHG-0005 becomes effective remain governed by the policy that existed at their merge time and are not retroactively reclassified.

## Decision

After this Change Record is merged to `dev`, the normal Gate 3 workflow becomes:

```text
Issue
→ short-lived branch from current dev
→ implementation + tests
→ Pull Request to dev
→ required CI green
→ Team Lead Verification
→ squash merge to dev
```

Independent peer review is optional and welcome, but it is not required for Definition of Done, merge authorization, Issue closure, or Gate 3 milestone promotion.

No reviewer is automatically requested solely to satisfy governance.

## Team Lead Verification gate

Before a Gate 3 PR is merged, the Team Lead must verify the applicable evidence below:

1. the PR is scoped to its Issue or explicitly documented implementation slice;
2. the branch is based on, rebased onto, or otherwise synchronized with the current integration state before final verification when necessary;
3. required CI checks are green;
4. lint/format, tests, migration-drift, Django system checks, and Docker/config checks required by the repository are green;
5. architecture and frozen-baseline boundaries are preserved;
6. migrations/model changes, when present, receive explicit schema review and are intentional;
7. material automated-review or manual-review findings are resolved or explicitly documented as accepted non-blocking limitations;
8. security/privacy-sensitive behavior relevant to the feature has regression coverage where practical;
9. documentation/contracts are updated when behavior changes;
10. the Team Lead explicitly authorizes the merge.

For documentation-only governance PRs, application-specific checks that cannot be affected remain non-applicable, while repository CI must still be green.

## Reviewer behavior

- Independent peer review remains allowed.
- A peer `APPROVED` review may be treated as additional evidence but is never required solely by Gate 3 governance.
- Reviewer requests must not be added automatically just to satisfy process.
- Automated review comments such as Codex findings are verification input, not a substitute for Team Lead Verification.
- Material automated findings must still be addressed or explicitly accepted before merge.

## Transition PR itself

The Pull Request carrying CHG-0005 is the one-time governance transition from the previous rule to this rule.

It is authorized by the Team Lead to merge with:

- documentation-only scope;
- green repository CI;
- explicit Team Lead verification;
- no mandatory independent peer approval.

For audit clarity, this transition PR is recorded as an explicitly authorized governance transition, not as evidence that the new policy existed before its merge.

CHG-0005 becomes effective only when that PR is merged to `dev`.

## Definition of Done impact

After CHG-0005 is effective, a Gate 3 Issue does not require independent peer review to be Done.

The relevant DoD requirement becomes:

- PR targets `dev`;
- required CI is green;
- Team Lead Verification is complete;
- merge is explicitly authorized by the Team Lead.

All technical quality, testing, architecture, security, migration, and documentation requirements remain unchanged.

## Milestone promotion impact

The Gate 3 `dev → main` milestone PR no longer requires an independent `APPROVED` review.

Before promotion, the Team Lead must verify:

- all mandatory Gate 3 scope is complete;
- Gate 3 closure checks are green;
- final full regression and Docker/bootstrap verification pass;
- baselines and governance records are synchronized;
- the milestone PR is green and explicitly authorized for merge.

## Compatibility with frozen baselines

CHG-0005 does not change BL-ARCH-002, BL-DATA-002, or BL-FOUNDATION-001 technical decisions.

It changes only Gate 3 repository-governance procedure. Existing architecture rules, Service/Selector boundaries, frozen invariants, migration controls, settings/environment controls, and runtime authorization records remain authoritative.

## Rollback

If the team later decides to restore mandatory independent approval, a new governance Change Record must explicitly supersede CHG-0005 and update the active workflow/DoD/milestone criteria.

Historical audit entries must never be rewritten to imply a review occurred when it did not.

**Decision:** approved by the Team Lead. Effective prospectively after the CHG-0005 transition PR is merged to `dev`.
