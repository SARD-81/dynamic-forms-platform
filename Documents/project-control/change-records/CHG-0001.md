# CHG-0001 — ERD Integrity and Clarity Patch

**Status:** APPROVED / APPLIED  
**Date:** 2026-09-20  
**Affected baseline:** BL-DATA-001  
**Resulting baseline:** BL-DATA-002

## Reason

Post-freeze review found integrity rules that were visually ambiguous or not sufficiently explicit as implementation constraints.

## Approved changes

1. Explicit `UNIQUE(process_run_id, process_step_id)` on ProcessStepRun.
2. Explicit `submission_id FK NULL UNIQUE`; ProcessStepRun owns the FK.
3. FormSubmission has no Process/ProcessRun/ProcessStep FK.
4. ProcessRun identity XOR constraint plus non-null resume-token uniqueness.
5. Explicit `UNIQUE(answer_id, option_id)` on AnswerOption.
6. Explicit Service-only Form/Process/Submission cross-table invariants.
7. Question/QuestionOption/ProcessStep ordering standardized as 1-based.
8. CLOSED Form rejects all new submissions.
9. Hard-delete behavior aligned with lifecycle/protective FK semantics.
10. Shared category naming fixed as `core.Category`.

## Technical notes

- Cross-table integrity remains Service-only because ordinary row-local CHECK constraints cannot enforce those relationships.
- Authenticated ProcessRun has respondent only.
- Anonymous ProcessRun has resume-token digest only.
- Raw resume tokens are never persisted.

## Impact

No entity is added or removed. Django models/migrations, Services, and tests must implement the tightened rules.

## Decision

Approved and applied. BL-DATA-002 supersedes BL-DATA-001.
